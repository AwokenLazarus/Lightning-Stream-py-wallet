# B2 signer socket API (agreed with XBT-060)

Newline-delimited JSON on a mode-600 Unix socket (`B2_SIGNER_SOCK`).
Request: `{"id":1,"method":"...","params":{...}}`.
The MCP process is a client of this socket. **Payer secrets never leave the signer.**

AGP-063 (review W): nothing on this socket moves coins except inside the owner's policy. `fund` to a bare
address is gone; the Rust signer funds only a channel for a payer key it issued, to the seller's verified
terms (`fund` with `origin`, `params`), and B2 issues no such keys, so B2 refuses every `fund`.

| Method | Params | Result |
|---|---|---|
| `fund` | `origin`, `params`, `sats` | AGP-063: `deny/fund_unbound` without `origin` and `params`, else `deny/bad_key` (B2 issues no client channel keys) |
| `sign_state` | `dest`, `cum` | policy-checked `{sig, chan, cum}`. AGP-063: the increase over what the ledger holds for the channel is booked (`xbt402:<chan>:<cum>`) before the signature, and the row is dropped if signing fails; a lower `cum` is `deny/amount` |
| `open_channel` | `dest`, `cap_sats?`, `expiry_blocks?`, `close_fee?` | opens a Spilman channel; cap defaults to `per_counterparty_cap_sats`. AGP-063: allowlisted `dest` only; payTo is the policy's `counterparties[dest].pay_to` (a different `pay_to` param is `deny/pay_to`); `cap_sats` ≤ `per_counterparty_cap_sats` (`channel_cap`), `expiry_blocks` in (`refund_margin_blocks`, max(`channel_expiry_blocks`, 4032)] (`expiry`), `close_fee` ≤ `close_fee_max_sats` (`close_fee`) |
| `channels` | — | `{channels:[{dest,chan,cap_sats,used_sats,expiry,residual_sats}]}` |
| `xbt402_pay` | `url`, `method`, `body`, `max_sats` | policy-checked 402 payment; streamed results: digest + stored path; provider body + receipt verbatim under `untrusted_provider_response` (untrusted data, not key-filtered). AGP-017: `verdict: pending, rule: funding_unconfirmed` while a new channel's funding waits for the offer's `minConf` (call again; the watcher also opens it). AGP-020: a signed state refused before the provider records it is re-sent on the next call (same cum and sig; at most one call of slack). AGP-063 W1: books the signed increase, not `charged`; the budget sums are held to that increase (`PolicyEngine.evaluate_booking`), and a dust floor above the remaining budget is refused before signing (`Xbt402Session.set_spend_check`) |
| `notice_hot_txid` | `txid` | register a send-to-hot UTXO |
| `fund_treasury` | `sats`, `expiry`, `signature` | 0x21 fund of the CSV-4320 treasury. AGP-080: only on the human's signature over `approval.treasury_fund_message(hot address, treasury address, sats, expiry)` (not an MCP tool). AGP-085: the outpoint is written to `treasury.json` (`pending_funding`) before the broadcast; only the node's own refusal takes it back, any other failure raises with it kept, and the start and the watcher settle it. `{ok: false, rule: treasury_funding_pending}` while an earlier funding is unsettled; `treasury_pending_outpoint` / `treasury_unsettled_outpoints` in the status |
| `recover_treasury` | `signature`, `expiry`, `to` | human-signed CSV recovery (not an MCP tool). AGP-080: the signature is over `approval.treasury_recover_message(treasury address, to, expiry)`, so it pays only the address it names |
| `close_channel` | `counterparty` | cooperative close through the signer (payer close sig); marks the channel `closed`. MCP tool. AGP-080: `close_proven` says whether this wallet's own node saw the funding output spent. If not, the record keeps `close_unproven`: the watcher proves it later (action row with `close_proven`), or refunds the channel at expiry as if it were open, and no new channel to that dest opens meanwhile (`deny/close_unproven`) |
| `xbt402_refund` (alias `refund_channel`) | `counterparty` (origin, dest or chan id) | AGP-013. The payer's CLTV refund (B1 `refund_tx`) of an open channel at or past its expiry, always to the current hot key. `deny/refund_early` before expiry, `deny/channel_closed` if a close spent the funding, `already: true` + the first txid if refunded. MCP tool. |
| `watch_tick` | — | AGP-013. One pass of the expiry watcher (also runs every `B2_WATCH_INTERVAL` s, default 10, inside `serve`): refund channels at expiry, sweep coins that reached a retired hot key |
| `forward_status` | — | AGP-013 forward rail: policy limits, 24 h forward spend, pending and delivered lots (no transfer hex). MCP tool. |
| `forward_recover` | `txid` | rebuild a forward transfer from a market's channel close (adaptor extraction), or void the purchase. A close that does not carry the pre-signature voids the lot only once it is in a block (AGP-089); until then the answer is `unconfirmed` and nothing changes. MCP tool. |
| `forward_pending` / `forward_transfers` | — | b5 AGP-008 names: pending purchases / delivered transfers with hex |
| `rotate_hot_key` | `expiry`, `signature` | AGP-013. New hot key; the old key's coins sweep into it (one 0x21 tx); the old key stays sealed as retired. AGP-063: human-signed (ed25519 over `rotate_message(hot_address, expiry)`, domain `xbt-agentwallet-hot-rotate-v1`, the Rust signer's); `deny/human_key`, `deny/human_sig` or `deny/expired` otherwise. Not an MCP tool |
| `sweep_hot` | `to`, `amount_sats`, `expiry`, `signature` | AGP-013. Human-signed (ed25519 over `sweep_message(hot_address, to, amount, expiry)`, `agentwallet-approve --sweep`) sweep out of the hot key, for the balance cap. Not an MCP tool |
| `signatures` | `limit?` | AGP-013. Tail of the signature audit log + `chain_ok`. AGP-016: `chain_ok` is checked against the witness's latest anchor; `chain` has the details, `anchor` the anchoring status |
| `anchor_now` | `reason?` | AGP-016. Anchor the log head with the witness now (the signer also does it at start, every `anchor_interval_s` in the watcher, and after every close, refund, sweep, rotation and treasury recovery). Not an MCP tool |
| `anchor_status` | — | AGP-016. Anchored line count and head, lines not yet anchored, the last error. Not an MCP tool |
| `hot_reconcile` | `scan?` (default true), `last?` | AGP-016. With `last`, report the last reconcile (the one at start) without running one. Otherwise re-check the hot UTXO set against the node (gettxout; with `scan`, scantxoutset over every hot key). Not an MCP tool |

Existing methods (`balance`, `quote_payment`, `pay`, `history`, `approve`, `recover_vault`) are unchanged. `pay` to a dest with a channel (or a registered `pay_to`) is an off-chain increment. An on-chain `pay` is booked before `sendtoaddress` (AGP-084): only the node's JSON-RPC error takes the row back; any other failure raises with the payment still in the ledger as `onchain:unconfirmed:<token>`, because the node may have sent it. `approve` holds its token (marked used on disk) while the payment runs (AGP-085): the node's JSON-RPC refusal or a policy deny frees it again until its expiry, a made payment removes it, and a crash or a payment of unknown fate leaves it used (`approval_replay`). A channel funding (`open_channel`, `xbt402_pay`, `pay` to a `pay_to`) whose broadcast fails without the node's own refusal keeps its pending record and payer key (`funding_unconfirmed` on the next `open_channel` until the node has the funding).

MCP tools are exactly: `balance`, `quote_payment`, `pay`, `history`, `channels`, `xbt402_pay`, `close_channel`, and since AGP-013 `xbt402_refund`, `forward_status`, `forward_recover`.

## AGP-013 custody

- **Hot key encrypted at rest.** `hot.json` and `channel_keys.json` hold AES-256-GCM ciphertext only. The wrapping key comes from the signer's environment: `B2_HOT_KEYFILE` (32 bytes, created 0600 if missing, refused inside the run dir) or `B2_HOT_PASSPHRASE` (scrypt N=2^17 since AGP-063, written as `log_n` in each blob; a blob without `log_n` is 2^15; only 15..18 are read; removed from `os.environ` once read). AGP-063: an existing keyfile (after symlinks) must be a regular file with no group or other bits. Without either the signer does not start (`B2_HOT_ALLOW_PLAINTEXT=1` for old demos only). A plaintext file from an older run is re-sealed on first start.
- **Rotation.** `rotate_hot_key` (human-signed since AGP-063); later coins to a retired address (a close's change) are swept by the watcher.
- **Balance cap.** Policy `hot_balance_cap_sats` (0 = off). Above it, opening a channel returns `deny/hot_balance_cap` with `action: human_sweep`.
- **Signature audit log.** `.run/signatures.jsonl`: one line per signature (`kind` funding / channel_state / channel_state_a3 / conditional_state / adaptor_presig / close_auth / refund / rotation_sweep / retired_sweep / human_sweep / treasury_recovery; `chan`, `dest`, amount, `sig_sha256`, signer `method`, policy `rule`), hash-chained (`prev`), O_APPEND + fsync. `sigaudit.verify_chain(path)`.
- **AGP-055: the policy ledger is an append-only log.** One process owns a wallet directory. `.run/ledger.payments.jsonl` (the policy ledger's payments) is an append-only log (`agentwallet/applog.py`): a header line `{"kind":...,"v":1}`, then one JSON object per line, each fsynced. A last line without its newline is a crash mid-append and is cut at start; any other line that does not parse stops the signer from starting (it never reads as a shorter log). The log is compacted (temp file, fsync, rename) once it holds over twice the rows still in use plus 1,024: payments are in use for the policy's longest window plus a day. `.run/audit.jsonl` keeps every commit. `channel_keys.json` is rewritten only when a key is added or dropped.
  - `.run/ledger.json` holds the pending approvals and `"payments_log": "ledger.payments.jsonl"`; it has no `payments` key. A `ledger.json` with `payments` from before AGP-055 is converted at the first start.
  - The Rust signer (`xbt-signer`) reads and writes the same files; its Lightning bookings add `{"amend": txid, "amount_sats": n | null}` lines to the payments log, which B2 applies when it loads one.
  - The routed locks this section used to describe (pre-sign and resolve, `.run/routing.json`, a channel record's `resolved` bookings) went with the routed signing: `docs/LIMITS.md` has what is left of them.
- **AGP-016: anchored log head.** A witness process (`python -m agentwallet.anchor serve --store DIR --sock PATH`), in production its own Unix user with a store directory the signer's user cannot write, receives the log lines added since its last anchor and accepts the new head only if they chain from it; a rewind, fork or head mismatch is refused and written to `alerts.jsonl`. The signer anchors at start, periodically (policy `anchor_interval_s`, default 60; checked on each watcher tick) and after every close, refund, sweep, rotation and treasury recovery. `sigaudit.verify_chain(path, anchor)` / `check_chain` fail when line `n` of the log no longer hashes to the anchored head, so a whole-file rewrite is detected. The signer refuses to start when its log fails the check; with policy `anchor_required: true` it also refuses to start without a reachable witness. Offline check: `python -m agentwallet.anchor check --store DIR --log .run/signatures.jsonl`.
- **AGP-016: hot UTXOs persist.** `.run/hot_utxos.json` holds the hot key's coins (current and retired keys), AES-256-GCM sealed under the hot wrapping key and rewritten on every change. At start the signer reconciles: a stored coin the node no longer has turns stale (kept and rechecked, not spent or counted), a coin whose script or value disagrees with the node is dropped, and `scantxoutset` adds confirmed coins the file lacks (`B2_HOT_SCAN=0` skips the scan). A node that is unreachable or in IBD leaves the stored set unverified. A tampered file stops the signer; move it aside and the next start rebuilds the set from the scan.
- **AGP-016: treasury secrets sealed.** `treasury.json` keeps the three pubkeys, the CSV and the funding outpoint in the clear; the human, cosigner and recovery secrets are one AES-256-GCM blob under the same wrapping key (AAD `b2/treasury-keys`). A plaintext file from before is re-sealed on first start.
- **Channel lifecycle.** `open` → `closed` | `refunded`. No new state is signed on a channel that is not open or is within `refund_margin_blocks` (default 6) of its expiry; a closed or refunded channel is replaced by a new one on the next payment.
- **Forward rail.** Policy `"forward": {"markets": [...], "per_lot_max_sats": N, "daily_budget_sats": N}` (absent = rail off); see `agentwallet/forward.py`.

## AGP-017 (signer-side)
- `health` also returns `chain`, `hrp` and `mining`, and `warnings` when `policy.json` holds a section the signer ignores (`routing`).
- `channels` lists a `pending` state (funded, open not yet accepted) with `funding_txid` and `open_error`.
- `forward_recover` takes an optional `blockhash` (a pruned node finds a confirmed close only with it).
- `sweep_hot` refuses a destination of another network's hrp and reports `fee_sats` (dust change included), `change_sats`, `outputs`.

## AGP-024 (light client)
- With `B2_CHAIN_BACKEND=electrum` the signer runs on Electrum servers (`docs/B2_CHAIN_BACKEND.md`); every method above behaves the same except: `balance` has `node_wallet: null` and `chain_backend: "electrum"` (no node wallet), an on-chain `pay` is `deny/light_backend`, `recover_vault` is unavailable, and the signer never mines.
- `health` adds `chain_backend` (light only): checkpoint, tip, `tip_age_s`, `tip_stale`, servers (`on_best_chain`, errors), `watched_scripts`, `verification_failures`.
- `chain_backend`: the same, after a header sync; `{"backend": "rpc"}` on the RPC path.
- A light signer whose servers answer but cannot serve the pinned checkpoint refuses to start (`ChainError` naming `B2_CHAIN`).
